# 做的人不是查的人

## 为什么

自己查自己，总会放过自己的错：做的人知道“我本来想写什么”，会把没写出来的部分自动脑补上。换一个只看结果的人来查，才能看到真实的样子。

## 谁来查

- 最低配：同一个 AI 工具，**开一个全新的对话**（不带刚才的聊天记录）。
- 更好：另一家的 AI。不同的模型，盲点不一样。
- 查的人**只读不改**：它只出问题单，改由做的人去改。

## 查的人拿到什么

只给三样，**不给做的人的自查结论**（免得被带偏）：

1. 任务单（尤其是“做完的标准”）；
2. 产出本身（文件位置）；
3. 原始材料（要核对事实时用）。

## 怎么查

1. 把“做完的标准”逐条列出来，一条一条对着产出核。
2. 能用程序核的先用程序核（数数量、比对原文、检查格式），再用眼睛看。
3. 再从使用者的角度过一遍：拿到这份东西的人，能不能直接用？哪里会看不懂、会卡住？
4. 事实、数字、引文：抽查，和原始材料对，对不上的列出来。

## 交回什么

```
结论：通过 / 不通过 / 未定

| 标准 | 结论 | 证据（文件哪里、实际看到什么） |
|---|---|---|

问题单（按严重程度排）：
1. 【必须改】在哪：…  问题：…  建议：…
2. 【建议改】…

只退回：<哪一步>（其余通过的不用重做）
```

## 规矩

- 没证据不能写“通过”，写“未定”。
- 只报问题，不顺手改文件。
- 不过的，只退回出错的那一步；同一步最多退 3 次，第 3 次还不过，交给主人决定。
- 查的标准开查前定好，查的过程中不改。
